# RCSS Arena — مخزن عمومی + Render رایگان

این بسته برای مخزن عمومی https://github.com/tahalkhaftan/RCSS-arena آماده شده است. سایت روی Render Free اجرا می‌شود و مسابقه‌ها با RCSSServer 19.0.0 روی GitHub Actions انجام می‌شوند. سورس رسمی سرور در vendor قرار دارد؛ این «سرور نصب‌شدهٔ قابل‌انتقال» نیست و Workflow آن را Build می‌کند.

## عمومی‌بودن چه معنایی دارد؟

کد سایت، ابزار اجرا و Workflow در مخزن عمومی قابل‌دیدن و کپی‌کردن هستند. عمومی‌بودن مخزن و مخفی‌بودن همان کد با هم ممکن نیست. برای رزومه، این پروژه را عمومی می‌گذاریم و کد/باینری تیم‌های فوتبال را داخل آن قرار نمی‌دهیم.

فایل‌های آپلودی و نتایج در مخزن خصوصی جداگانه ذخیره می‌شوند. برنامه قبل از دسترسی به داده‌ها خصوصی‌بودن آن مخزن را بررسی می‌کند و مخزن عمومی را رد می‌کند. دسترسی مدیر سایت و کسانی که به مخزن خصوصی دسترسی دارند برقرار است؛ این حفاظت، رمزنگاری سرتاسری نیست.

## نصب قدم‌به‌قدم

۱. فایل ZIP را استخراج کن. تمام محتویات پوشهٔ rcss-arena-public، شامل پوشهٔ مخفی .github، باید در ریشهٔ مخزن عمومی RCSS-arena روی شاخهٔ main باشد. فقط خود ZIP را آپلود نکن. اطلاعات تیم‌ها و رمزها را داخل این مخزن نگذار.

۲. یک مخزن دیگر با نام RCSS-arena-data بساز، حتماً Private، و هنگام ساخت Add README را فعال کن. این مخزن فقط محل نگهداری ZIP تیم‌ها، config.json، results.json و logs.zip است. هیچ Workflow مسابقه‌ای در آن قرار نمی‌گیرد. خصوصی‌بودن این مخزن را تغییر نده.

۳. یک Fine-grained personal access token مخصوص مخزن خصوصی بساز:
- Repository access: فقط RCSS-arena-data
- Contents: Read and write
- تاریخ انقضا تعیین کن.
در مخزن عمومی: Settings → Secrets and variables → Actions
- در Secrets، STORAGE_TOKEN = همین توکن
- در Variables، STORAGE_REPOSITORY = tahalkhaftan/RCSS-arena-data
توکن را در چت یا فایل منتشرشده نگذار.

۴. یک توکن جدا برای Render بساز، با دسترسی محدود به هر دو مخزن عمومی و خصوصی و Repository permissions شامل Contents=Read and write و Actions=Read and write. این توکن فقط به سرویس Render داده می‌شود. رمز GitHub لازم نیست.

۵. در Render مخزن عمومی را انتخاب کن:
New → Web Service → Docker → Instance type: Free
دیسک، Worker یا سرویس پولی نساز. فایل render.yaml هم تنظیمات پایه را دارد.

۶. Environment سرویس Render:
- ARENA_USER: نام ورود دلخواه به سایت
- ARENA_PASSWORD: رمز مستقل و طولانی سایت
- GITHUB_REPOSITORY: tahalkhaftan/RCSS-arena
- STORAGE_REPOSITORY: tahalkhaftan/RCSS-arena-data
- GITHUB_TOKEN: توکن جداگانهٔ Render در مرحلهٔ ۴
- GITHUB_REF: main

۷. Deploy کن. سایت را با HTTPS باز کن و نام و رمز سایت را وارد کن. دو ZIP از باینری Linux x86_64 تیم‌ها انتخاب کن و ابتدا یک بازی معمولی اجرا کن. بعد از شروع درخواست می‌توانی صفحه را ببندی؛ مسابقه روی GitHub ادامه دارد. برای نتیجه از «بازیابی آخرین تست» استفاده کن.

Workflow با نام RCSS Matches در Actions ظاهر می‌شود. release_id را سایت می‌سازد؛ فعلاً فرم دستی انتخاب حریف داخل Actions وجود ندارد و تنظیمات بازی از سایت وارد می‌شوند.

## سایر افراد چگونه استفاده می‌کنند؟

هر نفر پروژهٔ عمومی را Fork می‌کند، مخزن خصوصی دادهٔ خودش و سرویس Render خودش را می‌سازد، سپس نام مخزن‌ها و Secretهای خودش را تنظیم می‌کند. همه می‌توانند کد را ببینند و نسخهٔ مستقل راه بیندازند. این نسخه یک سایت مشترک با ثبت‌نام آزاد برای اجرای باینری ناشناس نیست. رمز سایت خودت را عمومی منتشر نکن.

## رابط و فرایند

Left و Right: فایل ZIP، نام تیم، پوشهٔ نسبی، دستور شروع.
تعداد دورها × تعداد بازی هر دور: تعداد کل بازی‌ها.
حالت: معمولی یا synch_mode، بسته به پشتیبانی تیم‌ها.
پس از هر بازی: نتیجه در JSON ذخیره می‌شود؛ بالای JSON خلاصهٔ برد، مساوی، باخت، گل و میانگین مالکیت نمایش داده می‌شود. پایان درخواست: ZIP شامل JSON و .rcg/.rcl و خروجی تیم‌ها و سرور قابل‌دانلود می‌شود.

مثال پوشه: AITech-2D/bin/
مثال دستور: ./start.sh -h {host} -p {port}
یا: ./localStartAll
دستور باید تمام ۱۱ بازیکن را اجرا کند. placeholderها: {host}، {port}، {coach_port}، {olcoach_port}. آرگومان‌ها باید مطابق اسکریپت واقعی تیم باشند. فعلاً فقط باینری ZIP پذیرفته می‌شود؛ Build سورس تیم در فرم پیاده نشده است.

مالکیت برآورد محدودهٔ قابل‌ضربهٔ بازیکنان در play_on است و چهار دستهٔ چپ، راست، آزاد و مشترک دارد. میانگین سادهٔ درصد بازی‌های کامل‌شده نمایش داده می‌شود. این عدد تعریف تحلیلی برنامه است و آمار رسمی مالکیت RCSS نیست؛ روش داخل JSON ذکر می‌شود.

## سهمیه و کیفیت

Runner استاندارد Ubuntu x64 مخزن عمومی طبق مستندات فعلی ۴ CPU، ۱۶GB RAM و ۱۴GB SSD دارد. اجرای استاندارد مخزن عمومی رایگان است، با محدودیت‌های سرویس و قوانین استفاده؛ به معنی VPS دائمی یا اجرای نامحدود بدون هیچ محدودیتی نیست. از Larger runner پولی استفاده نکن.

Render Free بعد از ۱۵ دقیقه بی‌ترافیک می‌خوابد و دیسک آن موقت است؛ چون مسابقه روی GitHub اجرا می‌شود و فایل‌ها در مخزن خصوصی هستند، خواب سایت نباید آن‌ها را از بین ببرد. پلن رایگان محدودیت ساعات، انتقال داده و Build دارد. بدون روش پرداخت، عبور از سهمیه معمولاً باعث توقف سرویس می‌شود. این برنامه تنظیمات Billing حساب را کنترل نمی‌کند.

- مجموع دو ZIP حداکثر ۳۲ MiB، هر درخواست حداکثر ۵۰ بازی.
- بازی‌ها ترتیبی، نه هم‌زمان؛ یک درخواست فعال برای هر سایت.
- Workflow تا ۱۵۰ دقیقه و هر بازی تا ۳۰ دقیقه. تعداد زیاد ممکن است از سقف Workflow عبور کند.
- توقف کنترل‌شده حدود ۳۰ ثانیه برای تشخیص نیاز دارد. Cancel workflow فوری ممکن است ZIP پایانی تولید نکند.
- نسخه برای تیم‌های مورد اعتماد است؛ جداسازی امنیتی مخصوص کد ناشناس ندارد. حذف توکن از محیط بازیکنان جای Sandbox واقعی را نمی‌گیرد.
- فایل‌های قدیمی را پس از دانلود از مخزن خصوصی حذف کن؛ ذخیره‌سازی بی‌نهایت فرض نشده است.
- CPU/RAM واقعی موردنیاز باید با تیم خودت و حریف اندازه‌گیری شود. GPU و مانیتور گرافیکی برای اجرای خود مسابقه لازم نیست.

## وضعیت آزمون

آزمون‌های محلی شامل لاگ مصنوعی، سرور UDP ساختگی، اعتبارسنجی ZIP و API گیت‌هاب ساختگی هستند. اجرای واقعی روی Render/GitHub و مسابقه با باینری تیم‌های تو هنوز تأیید نشده‌اند. تنظیمات درست و آزمون یک بازی واقعی آخرین مرحلهٔ راه‌اندازی است.

برای اجرای بررسی‌ها: python3 -m unittest discover -s tests -v
